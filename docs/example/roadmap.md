The register decides first, because a person saying a table is deprecated outranks the code saying it is live. Everything else is placed by where it sits between the design and the build.

## Changing where a table sits

All of this is read from the register, `.hunter/register.yml`. Lifecycle status is plain information and needs no reason:

```yaml
models:
  wh_commerce__legacy_fact:
    status: deprecated          # planned, building, live, deprecated, retired
    review_by: 2027-03-31       # the date it should be gone by
```

Marking a table verified is a confirmation, so it names the person:

```yaml
  wh_commerce__order_fact:
    persistence: verified
    verified_by: sav
    reason: signed off at the design review as the order fact of record
```
